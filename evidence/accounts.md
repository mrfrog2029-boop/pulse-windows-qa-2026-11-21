# Поиск, аккаунты и статусы друзей

Проверено на синтетических аккаунтах и тестовых релеях. Браузерные проверки запускали новые контексты Edge, обслуживали материалы приложения по loopback HTTP и перехватывали все WebSocket-запросы. Хранилища пользователя и публичная запись на релеях для этих проверок не использовались.

## Воспроизведение

- В исходной копии уже проходили 33 теста из `social.test.mjs` и `friend-replies.test.mjs`. Новые тесты дали восемь воспроизводимых ошибок. Среди них собственная карточка со старым relay key в выдаче, статус отсутствия при существующем vault, задержка первого heartbeat до cloud restore, отсутствие раннего повтора после отклонённого heartbeat и принятие неподписанного статуса.
- На исходном экране регистрации реле подтверждало vault, после чего Pulse показывал @ник. Второй клиент в этом состоянии не находил подписанную карточку. Когда отказ касался только публичной карточки, до публикации приватного контакта второй клиент также не мог разрешить выданный ID.
- При первом EOSE от доступного реле и отказе второго Pulse объявлял ник свободным. Доступное реле успевало принять vault и профиль ещё до того, как второе открыло запись прежнего владельца. В другом сценарии один повреждённый, но подписанный vault при неполном чтении давал сообщение «Неверный пароль».
- После появления трёх состояний статус кэшировался по логическому `isOnline`. Таймер приводил свежий статус «не в сети» к «неизвестно» без обновления списка. Отдельный тест зафиксировал переход.
- При получении двух подписанных копий одного автора вход восстанавливал более старую. Копия, подписанная другим relay key, открывала аккаунт, если внутренние данные удалось расшифровать. Оба результата воспроизведены в Edge.

## Поведение в исправленной копии

- Перед выдачей @ника экран регистрации получает подтверждение и для vault, и для публичной карточки. При неполном чтении учётная запись остаётся локальной, публикуется подписанный приватный контакт по ID, а проверка ника повторяется при доступном каталоге. Найденная позже запись владельца открывает предупреждение и оставляет чужой ник неопубликованным.
- Точный поиск по @нику и фильтр сохранённых друзей используют один способ сравнения. Для точного отсутствия нужны полные ответы на настроенных релеях. Частичное чтение сообщает о проблеме сети. Подписанная запись с недоступной карточкой сообщает о состоянии карточки, включая поиск без @.
- Сохранённая дружба остаётся привязанной к исходному Pulse ID и его P-256 ключам. Новый аккаунт с тем же ником появляется отдельным результатом. Для замены relay key сохранённого друга нужна приватная карточка с подписью того же P-256 ключа и совпадающим ключом обмена. Более старая карточка не откатывает уже принятую версию. Старая публичная карточка позволяет заполнить отсутствующие сведения у совместимых контактов и не заменяет закреплённый relay key.
- Heartbeat отправляется до окончания восстановления копии и повторяется на ближайшем восьмисекундном тике после отказа. Заявление о выходе подписывается и получает отдельный адрес события. Порядок сохраняется при выходе и повторном входе в ту же секунду. После истечения подтверждённого состояния список обновляет статус. Старая версия клиента продолжает применять собственное время жизни к последнему heartbeat.
- Удалённый вход выбирает свежую подписанную версию для каждого автора и сверяет ключ внутри расшифрованной копии с подписью каталога. Частичное чтение без подходящей копии оставляет результат проверки неопределённым.
- Восстановление и повторная запись cloud snapshot ждут полного чтения. Старая копия с одного реле не возвращает контакт, удалённый в актуальной копии на другом реле.
