Тест оставлял комнаты приватными. Каждый хозяин считывал отображённый приложением код, передавал его через штатную зашифрованную личку, а гость вводил этот код в интерфейсе Pulse. В каждой комнате оба клиента увидели друг друга и подтвердили получение тестовых сообщений. Роли пользовались обычным публичным набором Nostr-реле. [Отчёт роли A](hosted-pair-A.json), [отчёт роли B](hosted-pair-B.json)

В итоговом задании совпали SHA-256, идентификатор сборки и встречные отпечатки синтетических аккаунтов. Отличие VM подтверждено по двум разным SHA-256 значения `compute/vmId` из Azure IMDS, вычисленным с идентификатором этого прогона. В JSON сохранены хэши идентификаторов VM. [Итоговое задание](https://github.com/mrfrog2029-boop/pulse-windows-qa-2026-11-21/actions/runs/44898684361/job/136829970590), [документация Azure IMDS](https://learn.microsoft.com/en-us/azure/virtual-machines/instance-metadata-service)

Этот прогон подтверждает поиск и присутствие, обмен через личку, вход по коду и текст в двух комнатах на двух Windows Server 2022 VM. Медиа, исходный EXE, Windows Server 2025 и полное удаление относятся к отдельным сценариям проверки.
