# Полное удаление Pulse

`Pulse-Cleanup.exe` версии 1.0.0.0 — отдельное Windows-приложение. При запуске оно ищет экземпляры и показывает предпросмотр. Флажок подтверждения и диалог с отдельным подтверждением включают действие «Полностью удалить Pulse». Итоговый список показывает выполненные действия, сохранённые объекты, остатки и непроверенные области, включая причины для повторного поиска, повышения прав и возможной перезагрузки.

SHA-256 поставочного `Pulse-Cleanup.exe` — `FB6929E3A8BB334290912F1082A0B19776C82D9C244F32DBAB937EDE303A6F73`. Размер — 140 800 байт.

Старый механизм `--uninstall` отсутствует в последовательности действий очистителя. Пути и команды, прочитанные из Windows, служат только для проверки принадлежности.

## Границы операций

- Стандартный поиск включает типовые места установок, доступные известные профили, ссылки Windows и образы процессов. Для переносимых копий доступны «Добавить папку…» и «Добавить EXE…». Произвольные непроверенные каталоги перечисляются в результате.
- Очистка файлов работает с нормализованными локальными путями NTFS. Компоненты открываются относительно удерживаемого дескриптора родителя. Точки повторной обработки, облачные файлы, каталоги с учётом регистра, многосвязные файлы и альтернативные пользовательские потоки пропускаются. Перед удалением перепроверяются идентификатор, состояние и контрольная сумма там, где она применима. Удаление происходит через дескриптор, а каталоги удаляются только пустыми. [Относительное открытие](https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntcreatefile), [удаление через дескриптор](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle)
- Во время повторной попытки принадлежность данных или записей Windows должна по-прежнему проверяться. Поэтому при блокировках сохраняются нужные подтверждающие файлы. Отчёт перечисляет эти файлы и объясняет, почему они остались.
- Если таблицы LevelDB заняты, заранее показанный профиль повторно проверяется после завершения Pulse. Для этого должны совпасть исходные идентификаторы каталога данных и профиля, конфигурация и SHA-256 загрузчика. До установления принадлежности файлы профиля сохраняются. Несовпадение идентификатора и признаки общего хранилища прекращают обработку этой области.
- Штатный Evergreen WebView2 может иметь несколько жёстких ссылок на образ процесса EdgeCore. Для подтверждения процесса этот образ открывается отдельным путём только на чтение. Права удаления образа при этом отсутствуют.
- Кэш No-Vary-Search проверяется только внутри выделенного профиля по точному пути `EBWebView\Default\Cache\No_Vary_Search`. Для `journal.baj` и `snapshot.baf` нужны соответствующие двоичные заголовки Chromium версии 1 или 2. Перед удалением перепроверяется SHA-256. Другие каталоги, имена и несовпадающие заголовки сохраняются. [Имена и заголовки Chromium](https://chromium.googlesource.com/chromium/src/+/dd560d02dff805394dfe709b934a8e0f81f1f86d%5E%21/)
- Записи Windows и задачи заново читаются непосредственно перед операцией. Доступные интерфейсы реестра и Планировщика в этой реализации не дают атомарного сравнения и удаления при параллельной внешней правке. Живые сценарии для этих интерфейсов вынесены отдельно.
- Удаление охватывает локальные данные. Удалённые сервисы и relay сохраняют собственные аккаунты и события. Файл запущенной утилиты можно удалить после закрытия окна.

## Сборка и запуск проверки

Сборка выполняется в PowerShell 7 из корня проекта. Требуются Windows 10 версии 1803 или новее, .NET Framework 4.8 для Windows Forms и .NET SDK 8.0.425 для Roslyn. Сборщик записывает в EXE контрольную сумму явно переданного итогового `Pulse.exe`.

```powershell
.\cleanup\build.ps1 -PulseArtifact .\release\Pulse.exe
Get-FileHash -Algorithm SHA256 -LiteralPath .\release\Pulse-Cleanup.exe
```

Изолированная консольная сборка использует то же файловое ядро, отдельную точку входа и только синтетический корень с маркером под `test-runs`. Её процессный сценарий требует явно собранного хэша фикстуры и заданных PID. Рабочие реестр, службы, задачи и профили Windows из неё не очищаются.

```powershell
.\cleanup\build.ps1 -Test
$root = Join-Path $PWD ('test-runs\cleanup-accept-' + [Guid]::NewGuid().ToString('N'))
$fixture = (Resolve-Path .\cleanup\test\Pulse-Cleanup.Fixture.exe).Path
.\cleanup\tests\Fixture.Acceptance.ps1 -Root $root -FixtureExe $fixture
.\cleanup\tests\DeferredProfileAcceptance.ps1 -FixtureExe $fixture
.\cleanup\tests\RuntimeImageEvidence.ps1
& $fixture --integration-unit
```

Проверка с работающим WebView2 использует известную переносимую сборку и отдельный синтетический каталог.

```powershell
.\cleanup\build.ps1 -Test -PulseArtifact .\release\Pulse.exe -FixtureImage .\release\Pulse.exe
.\cleanup\tests\PortableRuntimeAcceptance.ps1 -PulseExe .\release\Pulse.exe -FixtureExe .\cleanup\test\Pulse-Cleanup.Fixture.exe
```

Для обычного запуска откройте `Pulse-Cleanup.exe`, проверьте список, добавьте переносимые копии при необходимости и подтвердите удаление. Проверьте отчёт, затем запустите новый `Pulse.exe` и пройдите установку. Повторный поиск помогает разобрать остатки, отдельно указанные утилитой.
