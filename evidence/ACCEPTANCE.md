На двух одноразовых Windows Server 2022 Datacenter x64, сборка 20348, прошли все восемь проверок каждой роли и итоговая сверка. Сопоставлены одна сборка, два разных идентификатора виртуальных машин и встречные отпечатки ключей аккаунтов. WebView2 `131.0.2903.86`. [Протокол двух VM](hosted-pair.md), [завершённый прогон GitHub](https://github.com/mrfrog2029-boop/pulse-windows-qa-2026-11-21/actions/runs/44898684361)

В итоговом прогоне с очистителем `FB6929E3…` после штатной очистки на Server 2022 прошли 12 из 12 проверок. При перезапуске предыдущий процесс WebView2 освобождал старый профиль. Новый процесс открывал прежнюю сессию и восстанавливал обмен сообщениями. На образе Server 2025 сборки 26100 WebView2 `157.0.4341.46` запускался с правильным каталогом, но параметры CDP для управления окном отсутствовали у процесса браузера. На этом образе автоматический сетевой прогон остался BLOCKED. [Итоговый протокол переустановки](exe-post-clean-2022.json), [диагностика Server 2025](native-startup-2025.json)

На Windows 11 Home x64, сборка 26200, у A и B были разные PID, Win32 desktops, каталоги `--user-data-dir` и браузерные сессии. До проверки сети тест сверял метку сборки и байты ресурсов, которые получил WebView2. На публичных релеях обе стороны подтвердили доставку каталогов и сообщений. Управляемое отключение проверялось на собственном WSS-релее. ## Что удалось воспроизвести

- Прежний интерфейс показывал @ник после записи зашифрованной копии аккаунта, хотя публикация публичной карточки могла ещё не пройти. Неполные ответы каталога также позволяли объявить ник свободным. Новая версия проверяет подтверждение публикации карточки и полноту отрицательного ответа. Старые друзья сопоставляются по подтверждённой идентичности при смене ключа релея. [Проверки аккаунтов](accounts.md)
- Получение иных сетевых данных превращало неизвестный статус в «не в сети». После выхода старого клиента друг не получал немедленного подтверждения. Новая версия отдельно показывает неизвестное состояние и обрабатывает подписанные события присутствия и выхода в порядке их появления. [Проверки аккаунтов](accounts.md), [проверки транспорта](transport.md)
- Прежняя версия открывала приватную комнату при вводе произвольного кода правильного формата. При недоступном прямом соединении два клиента также могли видеть разный состав участников. Теперь новый приватный код требует ответа участника, а сохранённая или публичная пустая комната показывает ожидание. [Комнаты](rooms.md), [исходный прогон](exe-baseline-loopback.json)

На исходных активных ресурсах при работающей сети встречный поиск и появление online после принятия дружбы проходили. Стабильно повторить конкретный случай двух пользовательских устройств не удалось. Недоступны журналы сети за время этого сбоя. Если он повторится, для сопоставления достаточно двух журналов «Настройки → Сеть → Скопировать журнал сети» с одной попытки. На публичной сети доставка аудио через TURN и VDO.Ninja в этих прогонах не подтверждена. [Транспорт](transport.md), [публичные реле́и](exe-release-public.json)

Подтверждённая служба исчезла со своим ключом реестра, посторонняя осталась зарегистрирована. У обеих копий A/B отсутствовали прежние `EXE`, `INI`, `Data` и WebView2. [Windows Server 2022](cleanup-2022.json), [Windows Server 2025](cleanup-2025.json), [итоговый запуск GitHub](https://github.com/mrfrog2029-boop/pulse-windows-qa-2026-11-21/actions/runs/44899839059)

Очиститель проверяет известные SHA-256, привязку путей и конфигурации к подтверждённой установке, признаки отдельного профиля WebView2, цели ярлыков, задач и служб. Для процессов он сверяет исполняемый образ и происхождение. В пользовательских загрузках и смешанных хранилищах остаются файлы, для которых принадлежность Pulse не доказана. Утилита объясняет остатки, занятие файлов и пределы доступных прав. [Признаки принадлежности](cleanup.md), [испытания сохранности](cleanup-qa.md)

В изолированной файловой проверке на Windows сохранены посторонние документы, одноимённый процесс, цель junction, жёсткие ссылки, альтернативный поток и данные другого origin. Принудительные ошибки Windows 32 и 5 появлялись в отчёте и совпадали с реальным состоянием диска. В первых прогонах штатного GUI на GitHub реестр, ярлык, служба и старый updater были обработаны как ожидалось. Во втором прогоне нужная задача исчезла и посторонняя сохранилась. Подтверждённый дочерний WebView2 завершился. Отчёт тогда пропустил положительные записи об обоих действиях. [Второй прогон Windows Server 2025](https://github.com/mrfrog2029-boop/pulse-windows-qa-2026-11-21/actions/runs/44897674877)

Восстановленная управляемая оболочка берётся из приложенного `Pulse.exe`. Пересборка требует этого файла. Исходный updater содержит побайтную копию исходного приложения. Итоговая повторная сборка обоих файлов совпала по SHA-256. Прошли 146/146 регрессий Node и 8/8 проверок упаковки. Независимый проверяющий сверил активные ресурсы, границы очистки, контрольные суммы, идентичность обеих VM и отчёты.
