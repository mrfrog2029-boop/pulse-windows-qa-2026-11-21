## Как выбирается веб-пакет

| ZIP внутри исходного `Pulse.exe` | Положение | Размер | Файлов | SHA-256 |
| --- | --- | --- | --- | --- |
| Активный `web.zip` | `.pweb`, файловое смещение `0x20AD04` | 464 934 | 20 | `878a94908a5433c145a3bbe895921f653eb4ec7f1fc6d1205645c5a8faaabae7` |
| Архив старой упаковки | `.text`, файловое смещение `0xD26CC` | 315 044 | 11 | `55b5d17ae14e22a2c52ddc09abcdd6af717c635dadaf04af77ef8315b1be6aa2` |

**PASS.** CLR указывает на каталог ресурсов с RVA `0x148000` в `.pweb`. `Pulse.MainForm.LoadWebFiles` читает `GetManifestResourceStream("web.zip")` и раскладывает файлы в словарь байтов в памяти. `InitWeb` перехватывает `https://app.pulse.invalid/*`, находит байты по пути и открывает `https://app.pulse.invalid/index.html`. В исходной оболочке ответ содержит `Cache-Control: no-cache`. В исправленной сборке для ресурсов приложений используется `Cache-Control: no-store`. Сохранение origin даёт WebView2 доступ к существующим данным этого origin.

`Pulse.ini` лежит рядом с EXE. Отдельно заданный `data` используется как путь к данным. Если ключ отсутствует, применяется соседний каталог `Data`. У установки здесь фактически задан `data=D:\Pulse\Data`. Профиль WebView2 расположен в `<data>\WebView` с данными в `EBWebView\Default`. Нативный загрузчик извлекается при отсутствии `<data>\bin\1.4.0\WebView2Loader.dll`. Лог расположен в `<data>\pulse.log`. `lib.Core.dll` и `lib.WinForms.dll` загружаются из ресурсов в память. Реальные загрузки пользователя помещаются в `<UserProfile>\Downloads\Pulse`.

Обычный запуск использует `Local\exepcstudio.Pulse.instance` и `Local\exepcstudio.Pulse.show`. Второй процесс подаёт сигнал первому и завершается. Поэтому две точные копии baseline с разными INI делят один mutex в текущей Windows-сессии. Статический анализ показал, что команда `--uninstall` старой оболочки останавливает процессы по имени и вызывает `cmd.exe` для рекурсивного удаления настроенного каталога данных.

## Воспроизводимая сборка

```powershell
python -B .\build.py --source .\baseline\Pulse.exe --web-dir .\web --output .\release\Pulse.exe
python -B .\tests\package_test.py -v
```

Сборщик по умолчанию проверяет исходную оболочку, обрабатывает активные managed resources и собирает изменённую оболочку через SDK `ildasm`, `csc` и `ilasm`. Начальная точка сборки для поставки — сохранённый исходный EXE в `baseline`. Флаг `--preserve-host` доступен для статического сравнения со старой оболочкой. При нестандартной установке SDK пути задаются переменными `PULSE_ILDASM`, `PULSE_CSC` и `PULSE_ILASM`.

Итоговый EXE содержит один активный `web.zip`. Сохранены FileVersion `1.4.0.0`, ProductVersion `1.4.0`, имя сборки .NET `Pulse, Version=1.4.0.0`, Win32 иконки, манифест, сведения о версии и остальные ресурсы .NET. Сборщик выводит SHA-256 всего EXE и 16-символьный идентификатор содержимого. В интерфейсе его показывает `#app-build-id` во вкладке настроек «Система». `meta[name="pulse-build-id"]` содержит тот же идентификатор уже при загрузке HTML. Изменение веб-файла меняет идентификатор. Две сборки из одного набора входов совпали побайтно. Проверка упаковки — **PASS, 8 из 8**.

**PASS.** В настоящем WebView2 после закрытия через `WM_CLOSE` в тестовой папке заменили EXE, сохранив путь к `Data`. После перезапуска идентификатор сборки во вкладке «Система» и HTML сменился с `c2cc5ce3e98ddf81` на `80293d705da414d1`, а `/js/net.js` совпал по SHA-256 с новым входным файлом. В обоих запусках CDP для `/index.html` и `/js/net.js` зафиксировал HTTP 200, `Cache-Control: no-store`, `fromDiskCache=false` и `fromServiceWorker=false`. Origin и контрольное значение `localStorage` сохранились. Проверка использовала две промежуточные сборки и отдельный тестовый профиль.

## Изолированный запуск

В каждой временной папке размещаются собственные копии `Pulse.exe` и соседний `Pulse.ini` со следующим содержимым.

```ini
portable=1
data=D:\полный-путь-к-тестовой-копии\Data
tray=0
autostart=0
```

Команда запуска в каждой папке — `Pulse.exe --portable --devtools`. Свой дочерний каталог `Data` нужен для каждой копии. Оболочка проверяет абсолютный путь к соседнему `Data` и отклоняет точки повторной обработки. При запросе portable-режима с некорректной конфигурацией она завершается с кодом 2. SHA-256 канонического пути к `Data` дополняет имя mutex и события. В portable-режиме отключены установка, удаление, системный трей, автозапуск, горячие клавиши и системные уведомления. Оболочка пропускает запись INI и реестра в `setSystem`. Переменная `WEBVIEW2_USER_DATA_FOLDER` задаётся только в процессе на `<data>\WebView`.

**PASS.** На временной копии с хэшем `00a72df3044d20d14103f21ad1dcba044c3a280445817ab35613d710a15d84c3` проверены отказ при отсутствии INI, отказ при пути вне собственного `Data` и отказ от команд установки/удаления в portable-режиме. Каждая команда вернула 2. Отдельный процесс `--uninstall` в обычном режиме показал текст «Для полного удаления запустите „Полное удаление Pulse“ из папки поставки». После нажатия OK процесс завершился с кодом 0. EXE, INI, контрольный файл данных и значения `HKCU` для Run и регистрации Pulse совпали до и после проверки. Эту же команду содержит штатная запись `UninstallString`. Проверка проведена запуском команды на временной копии, без выполнения регистрации в системном интерфейсе Windows.
