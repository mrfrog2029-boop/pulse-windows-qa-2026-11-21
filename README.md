# Pulse для Windows x64

Сборка `71446d0e81b0c49e`. Идентификатор виден в «Настройки → Система». Версия файла оболочки в свойствах Windows — 1.4.0.0. `Pulse-Cleanup.exe` — отдельная утилита «Полное удаление Pulse» версии 1.0.0.0.

## Очистка, установка, проверка

1. Закройте Pulse. Сохраните комплект новой версии вне каталогов старой установки и вне дополнительных папок, выбранных для очистки. Если пользуетесь ZIP поставки, сначала извлеките только `Pulse-Cleanup.exe`.
2. Откройте `Pulse-Cleanup.exe`. Проверьте список найденных установок, процессов, профилей WebView2 и интеграций Windows. Для переносимых копий добавьте их каталоги. Очистка удаляет локальные ключи, аккаунты, настройки и историю из подтверждённых хранилищ. Возможность входа по @нику и паролю зависит от доступности ранее опубликованной зашифрованной копии. Данные на релеях сохраняются.
3. Если список соответствует ожидаемому, подтвердите предупреждение и нажмите **«Полностью удалить Pulse»**. Сверьте результат, остатки, причины и непроверенные области. При занятом файле закройте удерживающую его программу и повторите сканирование. Для защищённой системной установки может потребоваться запуск с повышенными правами.
4. Извлеките новый `Pulse.exe` из комплекта и запустите его. Выберите каталог в установщике. В настройках проверьте идентификатор сборки. В окне или меню «Удаление Pulse» Windows указано название отдельной утилиты для полной очистки. Исходный updater хранится только среди образцов для испытаний.
5. На двух клиентах войдите под разными аккаунтами. Для поиска используйте @ник, который Pulse показывает как опубликованный, либо скопированный ID друга. Заявка требует принятия. Создайте комнату на первом клиенте, введите её код на втором, проверьте двух участников и обмен сообщениями в обе стороны. При своих адресах WSS на обоих клиентах нужен общий работающий релей.
6. Для разбора отдельного сбоя на каждом клиенте откройте «Настройки → Сеть → Скопировать журнал сети». В журнал входят сборка, время, номера попыток, ответы релеев и сокращённые отпечатки для сопоставления клиентов. Вводимый ник, пароли, ключи, текст сообщений и сам код комнаты в него не записываются.

## Сборка

В архиве стенда `pulse-inputs.zip` каталог `release` содержит поставку, `baseline` содержит два исходных EXE для регрессии. Восстановленный проект состоит из изменённых веб-ресурсов, преобразования управляемой оболочки в `host`, скрипта упаковки и исходников очистителя на C#. Бинарный вход исходной оболочки требуется для пересборки.

Проверено на Windows x64 с Python 3.13.14, .NET SDK 8.0.425, .NET Framework 4.x, ILDasm из Windows SDK / .NET Framework Tools и x64 ILAsm. Для локальных веб-тестов использованы Node.js 24, Edge WebView2, Git for Windows с OpenSSL, playwright-core 1.65.1 и ws 8.23.0.

```powershell
.\Build.ps1 -Source .\baseline\Pulse.exe -OutputDirectory .\release
Get-FileHash -Algorithm SHA256 -LiteralPath .\release\Pulse.exe, .\release\Pulse-Cleanup.exe
node --test tests/*.test.mjs
python -B -m unittest discover -s tests -p package_test.py -v
```

Первая команда проверяет входной SHA-256, пересобирает активный `web.zip` с новым build ID, собирает Windows-оболочку, привязывает очиститель к точному файлу этого выпуска и пишет `SHA256SUMS.txt`. Условия и команды запуска нативных клиентов находятся в `tests/exe-acceptance.mjs`, пользовательские каталоги для этих прогонов не требуются.

## Стенд GitHub Actions

Штатная очистка и переустановка рассчитаны на одноразовую виртуальную машину Windows Server 2025 x64. Сценарий `cleanup-hosted.ps1` создаёт на ней собственные тестовые установки и интеграции, запускает реальное окно очистителя и проверяет остатки. После освобождения двух старых каталогов `exe-acceptance.mjs` помещает в них точный EXE из поставки и проверяет обмен между новыми аккаунтами. Для проверки через интернет предусмотрена отдельная пара виртуальных машин. Фактический образ Windows, сборка ОС, архитектура, WebView2 и контрольные суммы выводятся в сводке каждого запуска. Отчёты сохраняются как JSON в артефактах Actions.

Публичный репозиторий содержит проверочный архив и сценарии стенда. Пользовательская установка использует два файла из `release`. [Репозиторий и журнал запусков](https://github.com/mrfrog2029-boop/pulse-windows-qa-2026-11-21/actions)
